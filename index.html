✓ 1. Form input dengan atribut name dan value sesuai
Terpenuhi
  • Atribut Name: Setiap kolom input memiliki atribut name="nim", name="nama", name="jurusan", dan name="alamat". Atribut ini menjadi kunci indeks dalam array asosiatif $_POST di PHP.
  • Atribut Value pada Form Edit: Pada edit.php dan mode update di single-page, elemen input memuat atribut value="<?php echo htmlspecialchars($data['...']); ?>" agar data yang telah tersimpan di database langsung muncul di form.

✓ 2. Validasi input (tidak boleh kosong)
Terpenuhi
  • Client-side Validation: Seluruh elemen form (input text, select, textarea) dilengkapi atribut bawaan HTML5 required sehingga browser mencegah pengiriman formulir jika terdapat field kosong.
  • Server-side Validation: Backend PHP menerapkan proteksi berlapis menggunakan fungsi empty(trim($variabel)) pada proses_tambah.php, proses_edit.php, maupun fungsi tambah()/ubah(). Jika pengguna mencoba membypass lewat Inspect Element atau API, request langsung dibatalkan dan diarahkan ke notifikasi error.
✓ 3. Koneksi ke MySQL berfungsi dan sesuai konfigurasi
Terpenuhi
  • Konfigurasi Host & User: Dikonfigurasikan menggunakan fungsi standar mysqli_connect("localhost", "root", "", "db_kampus").
  • Error Handling: Dilengkapi validasi kondisional if (!$koneksi) { die("Gagal terhubung: " . mysqli_connect_error()); } untuk memutus proses dan memberikan pesan diagnostik jika MySQL belum berjalan.
  • Database Skrip: Tersedia file database.sql yang otomatis membuat database db_kampus dan tabel mahasiswa beserta 4 data sampel awal.
✓ 4. Implementasi operasi CREATE, READ, UPDATE, DELETE berjalan sesuai alur
Terpenuhi
  • CREATE: Form Tambah → POST → INSERT INTO mahasiswa (nim, nama, jurusan, alamat) VALUES (...).
  • READ: Query SELECT * FROM mahasiswa ORDER BY id DESC → iterasi while ($row = mysqli_fetch_assoc(...)) pada tabel HTML.
  • UPDATE: Ambil data lama via SELECT ... WHERE id = $id → tampilkan di form edit → submit POST → UPDATE mahasiswa SET ... WHERE id = $id.

Penjelasan Alur 6 Tahap Data CRUD

Urutan perpindahan data dari input pengguna hingga tersimpan dan ditampilkan kembali

1

Form HTML

Pengguna menginputkan data pada elemen <input name="nim"> dll. Atribut method="POST" dan action="proses_tambah.php" menetapkan protokol pengiriman.

2

HTTP POST

Saat tombol submit ditekan, browser membungkus seluruh data input ke dalam HTTP Request Body (bukan query string URL) menuju server backend.

3

Konversi Variabel & Validasi

PHP menangkap superglobal $_POST['nim'], memindahkannya ke variabel lokal $nim = trim(...), memvalidasi !empty(), dan melakukan sanitasi string.

4

Penyusunan Query SQL

PHP merangkai sintaks string query SQL, misalnya: INSERT INTO mahasiswa (...) VALUES ('$nim', '$nama', ...) sesuai operasi yang dilakukan.

5

Koneksi & Eksekusi MySQL

Fungsi mysqli_query($koneksi, $query) mengirimkan string perintah ke database engine MySQL melalui objek koneksi aktif $koneksi.

6

Tampil Kembali

Server melakukan redirect menggunakan header("Location: index.php?pesan=sukses"). Halaman index mengeksekusi SELECT dan merender tabel baru.

Pertanyaan Dosen yang Sering Ditanyakan & Jawaban Tepat

Q1: Mengapa untuk form input dan update kita menggunakan metode POST, bukan GET? ▾
Jawaban: Karena metode POST mengirimkan data di dalam request body HTTP, bukan sebagai query string di URL browser. Hal ini mencegah data tampil di history/address bar browser, lebih aman dari manipulasi URL, serta tidak memiliki batasan panjang karakter seperti URL pada metode GET. Metode GET lebih tepat dipakai untuk operasi yang tidak mengubah kondisi data (misal pencarian atau membuka halaman edit berdasarkan ID).
Q2: Apa fungsi <input type="hidden" name="id"> pada form edit? ▾
Jawaban: Input bertipe hidden berfungsi untuk menyimpan nilai ID unik data mahasiswa secara tidak kasat mata bagi pengguna. Ketika form disubmit via POST ke proses_edit.php, ID tersebut disertakan agar query SQL dapat menyusun klausa spesifik WHERE id = $id. Tanpa klausa WHERE id, perintah UPDATE akan menimpa seluruh baris data di tabel.
Q3: Mengapa tidak cukup hanya mengandalkan atribut 'required' di HTML5? ▾
Jawaban: Atribut required adalah validasi di sisi browser (client-side) yang sangat mudah dihapus atau dimatikan oleh pengguna menggunakan fitur Inspect Element browser atau pengiriman request langsung via Postman/cURL. Oleh karena itu, wajib menyertakan validasi di sisi server (server-side) dengan empty(trim(...)) di PHP agar database tetap aman dari data kosong atau data spasi kosong.
Q4: Apa kegunaan fungsi mysqli_real_escape_string()? ▾
Jawaban: Fungsi mysqli_real_escape_string($koneksi, $input) digunakan untuk melakukan sanitasi terhadap karakter-karakter khusus SQL (seperti tanda petik tunggal ' atau tanda petik ganda "). Karakter tersebut akan di-escape (ditambahkan backslash \') sehingga tidak akan merusak struktur sintaks query SQL dan mencegah celah keamanan SQL Injection dasar.
Q5: Apa perbedaan arsitektur Single-Page (PetaniKode) vs Multi-Page (CodePolitan)? ▾
Jawaban: Pada arsitektur Multi-Page (CodePolitan), setiap tugas dipisah ke dalam file mandiri (separation of concerns: index.php untuk melihat, tambah.php untuk form, proses_tambah.php untuk eksekusi, dll), sehingga struktur kode rapi dan modular saat proyek bertambah besar. Sedangkan pada Single-Page (PetaniKode), seluruh operasi (C-R-U-D) ditangani dalam satu file yang sama menggunakan fungsi-fungsi PHP (tambah(), ubah(), hapus(), tampil_data()) dan routing internal via switch($_GET['aksi']).

Cara Menjalankan Script PHP & MySQL Lokal di Komputer

Untuk sesi demo di kelas bersama Pak Chandra menggunakan database MySQL lokal asli:

Langkah 1: Aktifkan MySQL di Laragon

  1. Buka aplikasi Laragon.
  2. Klik tombol Start All (memastikan Apache & MySQL aktif).
  3. Database db_kampus dan tabel mahasiswa sudah otomatis terpasang. (Jika ingin impor ulang, buka menu Database → Impor database.sql).

Langkah 2: Jalankan Server Demo

Cukup klik ganda (double-click) file:

JALANKAN_SERVER.bat

Atau jalankan manual via terminal:

php -S localhost:8000

URL Akses Demo Lokal:

  • Multi-Page CRUD: http://localhost:8000/crud-multi-page/
  • Single-Page CRUD: http://localhost:8000/crud-single-page/
